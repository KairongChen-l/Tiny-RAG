# 核心模块详解

本文档详细说明系统中各个核心模块的实现细节、设计决策和关键技术点。

## 3.1 文档摄取模块（ingestion）

### 支持的文档格式

- **Markdown** (`.md`, `.markdown`): 保留标题层级结构
- **PDF** (`.pdf`): 文本提取（需要PDF解析库）
- **纯文本** (`.txt`, `.text`): 简单文本文件

### 解析器实现

#### 注册表模式

使用 `ParserRegistry` 管理多个解析器：

```go
type ParserRegistry struct {
    mu      sync.RWMutex
    parsers map[DocumentFormat]Parser
}
```

**优势**：
- 运行时注册，无需修改代码
- 支持多格式扩展
- 线程安全

#### Markdown解析器

**实现要点**：
- 使用正则表达式识别标题层级
- 构建层次化的Section结构
- 保留文档的语义结构

**关键代码**：
```go
func (p *MarkdownParser) Parse(ctx context.Context, path string) (*Document, error) {
    // 读取文件
    content, err := os.ReadFile(path)
    
    // 解析Markdown结构
    sections := p.parseSections(string(content))
    
    // 构建Document对象
    doc := NewDocument(id, path, FormatMarkdown)
    doc.Sections = sections
    return doc, nil
}
```

### 错误处理

- **文件不存在**: 返回明确的文件路径错误
- **格式不支持**: 返回格式错误，包含支持的格式列表
- **解析失败**: 返回详细的解析错误，包含行号等信息

### 扩展性设计

**添加新格式的步骤**：
1. 实现 `Parser` 接口
2. 定义新的 `DocumentFormat` 常量
3. 注册到 `ParserRegistry`
4. 更新 `DetectFormat` 函数

## 3.2 文档分块模块（chunking）

### 分块策略

#### 结构感知分块

**实现**：`internal/chunking/semantic.go`

**算法**：
1. 遍历文档的层次化结构（Section）
2. 按标题层级识别分割点
3. 在段落边界处创建块
4. 应用大小约束（MinChunkSize, MaxChunkSize）
5. 添加重叠（Overlap）

**关键参数**：
- `MaxChunkSize`: 1000字符（默认）
- `MinChunkSize`: 100字符（默认）
- `Overlap`: 100字符（默认）

**优势**：
- 保持语义完整性
- 避免在句子中间切断
- 提高检索相关性

#### 语义分块（Embedding-based）

**实现**：`internal/chunking/embedding_semantic.go`

**算法**：
1. 将文档分割为句子
2. 对每个句子生成embedding
3. 计算相邻句子的余弦相似度
4. 相似度低于阈值（0.7）时创建块边界
5. Fallback到结构感知分块（如果embedding失败）

**优势**：
- 基于语义相似度，更智能
- 自动识别语义边界

**Trade-off**：
- 需要额外的embedding计算
- 成本更高，但质量更好

### 重叠机制

**实现**：
- 相邻块保留 ~100 字符重叠
- 避免信息在块边界处丢失
- 提高检索召回率

**示例**：
```
Chunk 1: "...这是第一段内容，包含重要信息..."
Chunk 2: "...重要信息，这是第二段内容..."
         ^^^^^^ 重叠部分
```

### 边界处理

- **段落边界**: 优先在段落结束处分割
- **标题边界**: 在标题前创建新块
- **大小约束**: 超过MaxChunkSize时强制分割
- **最小大小**: 小于MinChunkSize的块会合并

### 性能考虑

- **批量处理**: 支持批量文档分块
- **内存效率**: 流式处理大文档
- **并发安全**: 分块器无状态，可并发使用

## 3.3 向量嵌入模块（embedding）

### 多Provider支持

#### OpenAI Embedding

**模型**: `text-embedding-3-small` (默认)
**维度**: 1536
**特点**: 
- 高质量向量
- 支持批量API
- 精确的token计数

#### Ollama Embedding

**模型**: `nomic-embed-text` (默认)
**维度**: 768
**特点**:
- 本地部署，无需API Key
- 适合开发测试
- 成本低

### 缓存机制

#### 内存缓存

**实现**: `internal/embedding/cache_memory.go`

**特点**:
- 进程内缓存，速度快
- 支持TTL和最大条目数
- 自动清理过期条目

**缓存键格式**: `embed:{provider}:{model}:{hash(text)}`

#### Redis缓存

**实现**: `internal/embedding/cache_redis.go`

**特点**:
- 分布式缓存，多进程共享
- 支持TTL
- 适合生产环境

**成本优化**: 缓存命中可减少30-50% API调用

### 错误重试

**策略**:
- 网络错误: 自动重试（3次，指数退避）
- 限流错误: 自动重试，带退避
- 认证错误: 不重试，立即返回

**实现**: 集成 `pkg/retry` 包

### 成本优化

- **批量处理**: 减少API调用次数
- **缓存机制**: 避免重复计算
- **智能重试**: 避免无效重试

## 3.4 向量存储模块（index）

### SQLite + sqlite-vec实现

**表结构**:
- `documents`: 文档元数据
- `chunks`: 文本块数据
- `chunk_vectors`: 向量数据（sqlite-vec）
- `document_versions`: 版本快照
- `jobs`: 任务状态

**优势**:
- 零依赖部署（需要编译sqlite-vec）
- 单文件存储，易于备份
- 支持版本控制和软删除

**限制**:
- 适合中小规模数据（< 100万chunks）
- 需要CGO编译

### Qdrant实现

**特点**:
- 高性能向量检索
- 支持分布式部署
- 丰富的元数据过滤
- 无需CGO依赖

**适用场景**: 大规模数据（> 100万chunks）

### 增量更新机制

**实现**:
1. 计算文档内容hash
2. 与存储的hash比较
3. 如果不同，原子替换所有chunks
4. 使用事务保证原子性

**优势**:
- 避免重复处理
- 节省embedding成本
- 保证数据一致性

### 版本控制

**实现**:
- 存储文档版本快照
- 记录版本号、hash、chunk数量
- 支持恢复到指定版本

**限制**: 仅SQLite实现支持，Qdrant不支持

### 软删除

**实现**:
- `deleted_at` 字段标记
- 默认查询过滤已删除文档
- 支持恢复和硬删除

## 3.5 检索模块（retrieval）

### 向量检索

**实现**: `internal/retrieval/vector.go`

**流程**:
1. 将查询文本转换为向量
2. 在向量存储中搜索相似向量
3. 使用余弦相似度计算
4. 返回top-k结果

### BM25检索

**实现**: `internal/retrieval/bm25.go`

**算法**:
- TF (Term Frequency): 词频
- IDF (Inverse Document Frequency): 逆文档频率
- 文档长度归一化

**特点**:
- 基于关键词匹配
- 使用Snowball词干提取
- 支持索引chunks进行关键词检索

### 混合检索（RRF融合）

**实现**: `internal/retrieval/hybrid.go`

**融合策略**:

1. **RRF (Reciprocal Rank Fusion)** - 默认
   ```go
   score = 1 / (k + rank)
   final_score = sum(rrf_scores)
   ```

2. **Average**
   ```go
   final_score = (vector_score + bm25_score) / 2
   ```

3. **Max**
   ```go
   final_score = max(vector_score, bm25_score)
   ```

**优势**:
- 结合语义和关键词
- 提升召回率
- 平衡精度和召回

### 重排序（Reranker）

**实现**: `internal/retrieval/reranker/cohere.go`

**流程**:
1. 向量检索获取候选结果（top-20）
2. 使用Reranker重新排序
3. 返回最终top-k结果（top-5）

**模型**: `rerank-multilingual-v3.0`

**优势**: 提升20-30%准确率

### 查询重写和扩展

**简单重写器**:
- 去除停用词
- 大小写规范化
- 去除标点符号

**LLM重写器**:
- 使用LLM进行智能重写
- 查询扩展（同义词、相关概念）
- 多查询生成（Multi-Query）

### 元数据过滤

**支持**:
- 按文档格式过滤
- 按文档ID过滤
- 按自定义元数据过滤

## 3.6 提示词构建模块（prompt）

### 模板系统

**默认系统提示词**:
```
You are a helpful assistant. Answer the question based on the provided context.
Use the format [citation:x] to cite sources, where x is the context number.
If multiple contexts support a statement, cite all: [citation:1][citation:2].
If the context doesn't contain relevant information, say so.
Be concise and accurate.
```

### 上下文组装

**格式**:
```
Context:
[citation:1] Source: document.md, Section: Chapter1/Section2
This is the first chunk content...

[citation:2] Source: document.md, Section: Chapter1/Section3
This is the second chunk content...
```

### Token截断

**策略**:
1. 计算系统提示词和用户查询的token数
2. 计算可用上下文token数
3. 按引用顺序添加chunks
4. 超过限制时停止

**实现**: 使用tiktoken精确计算

### 引用格式

**格式**: `[citation:x]` (x为1-based编号)

**解析**: 自动解析LLM响应中的引用

## 3.7 LLM生成模块（generation）

### 多Provider支持

#### OpenAI
- 模型: GPT-4, GPT-3.5-turbo
- 特点: 高质量、流式响应

#### Anthropic
- 模型: Claude-3系列
- 特点: 长上下文支持

#### Ollama
- 模型: llama3.2, qwen2.5
- 特点: 本地部署，无需API Key

#### Kimi
- 模型: Moonshot系列
- 特点: 超长上下文（200K tokens）

### 流式响应

**实现**: 支持流式生成，实时返回结果

**优势**:
- 减少用户等待时间
- 支持取消操作

### 错误处理

**重试机制**:
- 网络错误: 自动重试（3次）
- 限流错误: 自动重试，带退避
- 认证错误: 不重试

**熔断器**:
- 防止级联失败
- 自动恢复机制

### Token管理

**计数**: 精确统计输入和输出token

**限制**: `MaxTokens`限制输出长度

**成本**: 可用于成本计算和监控

## 3.8 对话管理模块（conversation）

### 多轮对话支持

**实现**:
- 维护对话历史
- 支持上下文窗口管理
- 自动生成对话摘要

### 上下文管理

**实现**: `GetContextWindow(n)` 返回最近N条消息

**策略**: 从最新消息开始，向前取N条

### 历史记录存储

**当前**: 内存存储

**扩展**: 可集成持久化存储（数据库）

## 3.9 异步任务模块（job）

### 内存队列实现

**实现**: `internal/job/queue.go`

**特点**:
- 基于Go channel
- Worker Pool模式
- 简单高效

**限制**: 进程重启会丢失队列任务

### Redis队列实现

**实现**: `internal/job/queue_redis.go`

**特点**:
- 使用asynq库
- 任务持久化
- 支持分布式部署
- 自动重试机制

### Worker Pool模式

**实现**:
- 固定数量的worker goroutines
- 控制并发数
- 资源复用

### 任务状态管理

**状态**:
- `pending`: 等待处理
- `processing`: 处理中
- `completed`: 已完成
- `failed`: 失败

**进度追踪**:
- 阶段化进度更新
- 进度历史记录（最多20条）

## 3.10 监控指标模块（metrics）

### Prometheus集成

**指标类型**:
- Counter: 累计计数
- Histogram: 分布统计
- Gauge: 当前值

### 关键指标定义

**检索指标**:
- `retrieval_requests_total`: 请求总数
- `retrieval_duration_seconds`: 请求耗时
- `retrieval_results_count`: 返回结果数

**Embedding指标**:
- `embedding_requests_total`: 请求总数
- `embedding_cache_hits_total`: 缓存命中数
- `embedding_cache_misses_total`: 缓存未命中数

**LLM指标**:
- `llm_requests_total`: 请求总数
- `llm_tokens_total`: Token使用量
- `llm_errors_total`: 错误数

### 性能监控

**端点**: `/metrics`

**使用**: Prometheus抓取指标
