# 可靠性设计

本文档详细说明系统中的可靠性设计策略和实践。

## 错误处理策略

### 错误分类

#### 1. 可重试错误

**类型**:
- 网络错误（连接超时、连接拒绝）
- 限流错误（429 Too Many Requests）
- 服务暂时不可用（503 Service Unavailable）

**处理策略**: 自动重试（指数退避）

#### 2. 不可重试错误

**类型**:
- 认证错误（401 Unauthorized）
- 无效请求（400 Bad Request）
- 资源不存在（404 Not Found）

**处理策略**: 立即返回错误，不重试

### 错误处理实现

#### 重试机制

**实现**: `pkg/retry/retry.go`

**策略**: 指数退避

**配置**:
```go
config := retry.DefaultRetryConfig()
config.MaxAttempts = 3
config.InitialDelay = 100 * time.Millisecond
config.Multiplier = 2.0
config.MaxDelay = 5 * time.Second
```

**效果**: 
- 自动重试临时性失败
- 避免无效重试
- 减少用户感知的错误

#### 错误信息增强

**实现**: 详细的错误信息

**格式**:
```
Ollama API error (model: nomic-embed-text, base_url: http://localhost:11434): connection refused
```

**优势**: 
- 便于问题定位
- 包含上下文信息
- 支持错误追踪

- **用户体验**: 减少用户感知的错误
- **成本**: 略微增加API调用（重试）

## 熔断器（pkg/circuitbreaker）

### 实现

**状态机**:
- **Closed**: 正常状态，允许请求
- **Open**: 熔断状态，拒绝请求
- **Half-Open**: 半开状态，允许一次尝试

### 状态转换

```
Closed → Open: 失败次数达到阈值
Open → Half-Open: 超时后自动进入
Half-Open → Closed: 成功次数达到阈值
Half-Open → Open: 尝试失败
```

### 配置

```go
config := circuitbreaker.DefaultCircuitBreakerConfig()
config.FailureThreshold = 5  // 失败5次后开启
config.SuccessThreshold = 2  // 成功2次后关闭
config.Timeout = 60 * time.Second  // 60秒后尝试恢复
```

### 效果

- **防止级联失败**: 快速失败，保护系统
- **自动恢复**: 超时后自动尝试恢复
- **资源保护**: 避免无效请求消耗资源

## 限流（pkg/ratelimit）

### 实现

**算法**: 令牌桶算法

**特点**:
- 支持速率限制
- 支持突发请求
- 可配置时间窗口

### 配置

```yaml
server:
  rate_limit:
    enabled: true
    rate: 100        # 每秒100个请求
    burst: 200       # 突发200个请求
    window: 1s       # 1秒时间窗口
```

### 效果

- **API保护**: 防止API滥用
- **资源保护**: 避免资源耗尽
- **公平性**: 保证所有用户公平使用

## 优雅关闭

### 实现

**信号处理**: 
- SIGTERM: 优雅关闭
- SIGINT: 优雅关闭

**流程**:
1. 停止接收新请求
2. 等待正在处理的请求完成
3. 关闭资源（数据库、HTTP客户端等）
4. 退出进程

### 代码示例

```go
// 信号处理
sigChan := make(chan os.Signal, 1)
signal.Notify(sigChan, syscall.SIGTERM, syscall.SIGINT)

// 优雅关闭
<-sigChan
ctx, cancel := context.WithTimeout(context.Background(), 30*time.Second)
defer cancel()

// 停止服务
server.Shutdown(ctx)
queue.Stop()
store.Close()
```

### 效果

- **数据一致性**: 保证任务完成
- **用户体验**: 不中断正在处理的请求
- **资源清理**: 正确释放资源

## 数据一致性保证

### 策略

#### 1. 事务支持

**实现**: 数据库事务

**场景**: 
- 文档存储（原子替换）
- 版本控制（原子操作）

**效果**: 保证数据一致性

#### 2. 增量更新

**实现**: 基于hash的变更检测 + 原子替换

**流程**:
1. 计算新文档hash
2. 与存储的hash比较
3. 如果不同，原子替换所有chunks

**效果**: 避免部分更新导致的不一致

#### 3. 软删除

**实现**: `deleted_at` 字段标记

**效果**: 
- 数据可恢复
- 避免误删除
- 支持审计

### 效果

- **数据一致性**: 100% 保证
- **可恢复性**: 支持软删除恢复
- **审计能力**: 完整的操作记录

## 超时控制

### 实现

**所有外部调用都有超时**:
- LLM调用: 60秒（可配置）
- Embedding调用: 30秒（可配置）
- 数据库查询: 10秒（可配置）

### 配置

```yaml
generation:
  timeout: 60s

embedding:
  timeout: 30s

database:
  timeout: 10s
```

### 效果

- **避免长时间阻塞**: 快速失败
- **资源保护**: 及时释放资源
- **用户体验**: 明确的超时错误
