# 数据流详解

本文档详细说明系统中各个流程的数据流转和处理过程。

## 文档摄取流程

### 流程图

```
用户上传文档
  ↓
API接收 (POST /api/v1/documents)
  ↓
创建异步任务 (Job)
  ↓
Worker获取任务
  ↓
[10%] 解析文档 (ingestion.Parser)
  ├─ MarkdownParser → Document
  ├─ PDFParser → Document
  └─ TextParser → Document
  ↓
[30%] 检查文档hash (index.GetDocumentHash)
  ├─ 如果hash相同 → 跳过处理
  └─ 如果hash不同 → 继续处理
  ↓
[40%] 文档分块 (chunking.Chunker)
  ├─ 结构感知分块
  └─ 生成Chunks数组
  ↓
[50%] 生成Embedding (embedding.Embedder)
  ├─ 批量处理
  ├─ 缓存检查
  └─ 生成Vectors数组
  ↓
[80%] 存储文档 (index.VectorStore)
  ├─ 原子替换chunks
  ├─ 更新文档hash
  └─ 存储向量
  ↓
[100%] 任务完成
  ↓
更新任务状态 (JobStore.Update)
```

### 数据转换

```
文件 (bytes)
  ↓
Document {
  ID, Title, Source, Format,
  Sections: []Section {
    Title, Level, Content, Children
  }
}
  ↓
Chunks: []Chunk {
  ID, DocumentID, Content,
  SectionPath, Index, Metadata
}
  ↓
ChunksWithVectors: []ChunkWithVector {
  Chunk, Vector: []float32
}
  ↓
存储到数据库
```

### 关键点

1. **异步处理**: 不阻塞API响应
2. **增量更新**: 基于hash检测变更
3. **原子替换**: 保证数据一致性
4. **进度追踪**: 实时更新任务进度

## 文档处理流程

### 详细步骤

#### 1. 解析阶段

**输入**: 文件路径
**输出**: Document对象

**处理**:
- 根据文件格式选择解析器
- 解析文档结构（标题、段落）
- 提取元数据

**数据结构**:
```go
Document {
    ID: "doc-123",
    Title: "文档标题",
    Source: "/path/to/file.md",
    Format: "markdown",
    Sections: [
        {
            Title: "第一章",
            Level: 1,
            Content: "内容...",
            Children: [...]
        }
    ],
    Hash: "abc123..."
}
```

#### 2. 分块阶段

**输入**: Document对象
**输出**: []Chunk

**处理**:
- 结构感知分块
- 应用大小约束
- 添加重叠

**数据结构**:
```go
Chunks: [
    {
        ID: "chunk-1",
        DocumentID: "doc-123",
        Content: "这是第一块内容...",
        SectionPath: "第一章/第一节",
        Index: 0,
        Metadata: {...}
    },
    ...
]
```

#### 3. Embedding阶段

**输入**: []Chunk
**输出**: []ChunkWithVector

**处理**:
- 批量生成embedding
- 缓存检查
- 错误重试

**数据结构**:
```go
ChunksWithVectors: [
    {
        Chunk: {...},
        Vector: [0.1, 0.2, 0.3, ...]  // 1536维
    },
    ...
]
```

#### 4. 存储阶段

**输入**: []ChunkWithVector
**输出**: 存储完成

**处理**:
- 原子替换chunks
- 更新文档hash
- 存储向量

## 查询流程

### 流程图

```
用户提交查询 (POST /api/v1/query)
  ↓
解析请求 {query, top_k, ...}
  ↓
[可选] 查询重写 (retrieval.QueryRewriter)
  ├─ 简单重写: 规范化
  └─ LLM重写: 智能扩展
  ↓
查询向量化 (embedding.Embedder)
  ├─ 缓存检查
  └─ 生成查询向量
  ↓
向量检索 (index.VectorStore.Search)
  ├─ 相似度计算
  ├─ Top-K选择
  └─ 返回候选结果
  ↓
[可选] BM25检索 (retrieval.BM25Retriever)
  ├─ 关键词匹配
  └─ 返回候选结果
  ↓
[可选] 混合检索融合 (retrieval.HybridRetriever)
  ├─ RRF融合
  └─ 返回融合结果
  ↓
[可选] Reranking (retrieval.Reranker)
  ├─ Cohere Rerank
  └─ 重新排序
  ↓
构建提示词 (prompt.PromptBuilder)
  ├─ 组装上下文
  ├─ 添加引用
  └─ Token截断
  ↓
LLM生成 (generation.LLM)
  ├─ 调用LLM API
  ├─ 流式响应
  └─ 解析引用
  ↓
返回结果 {
  answer, citations, tokens_used
}
```

### 数据转换

```
用户查询: "什么是RAG？"
  ↓
查询向量: [0.1, 0.2, 0.3, ...]  // 1536维
  ↓
检索结果: []SearchResult {
    Chunk, Score: 0.95, Citation: 1
}
  ↓
RetrievedChunks: []RetrievedChunk {
    Chunk, Score: 0.95, CitationID: 1
}
  ↓
Prompt {
    SystemMessage: "...",
    UserMessage: "Context: [citation:1] ...\nQuery: 什么是RAG？",
    TokenCount: 1500,
    Citations: [...]
}
  ↓
Response {
    Answer: "RAG是检索增强生成...",
    TokensUsed: 2000,
    Citations: [1, 2]
}
```

### 关键点

1. **多路召回**: 向量检索 + BM25检索
2. **结果融合**: RRF融合策略
3. **重排序**: 提升检索精度
4. **上下文组装**: 智能截断和引用

## 对话流程

### 流程图

```
用户发送消息 (POST /api/v1/conversations)
  ↓
获取对话历史 (conversation.GetContextWindow)
  ├─ 获取最近N条消息
  └─ 转换为PromptMessage格式
  ↓
检索相关文档 (retrieval.Retrieve)
  ├─ 基于当前查询
  └─ 返回相关chunks
  ↓
构建提示词 (prompt.BuildWithHistory)
  ├─ 包含对话历史
  ├─ 包含检索结果
  └─ 组装上下文
  ↓
LLM生成 (generation.LLM)
  ├─ 调用LLM API
  └─ 生成回答
  ↓
保存消息 (conversation.AddMessage)
  ├─ 保存用户消息
  └─ 保存助手消息
  ↓
返回结果 {
  conversation_id,
  message_id,
  answer,
  citations
}
```

### 数据转换

```
对话历史: []Message {
    {Role: "user", Content: "什么是Go？"},
    {Role: "assistant", Content: "Go是..."},
    {Role: "user", Content: "它有什么特点？"}
}
  ↓
PromptMessages: []PromptMessage {
    {Role: "user", Content: "什么是Go？"},
    {Role: "assistant", Content: "Go是..."},
    {Role: "user", Content: "它有什么特点？"}
}
  ↓
检索结果: []RetrievedChunk {...}
  ↓
Prompt {
    SystemMessage: "...",
    UserMessage: "History: ...\nContext: ...\nQuery: 它有什么特点？"
}
  ↓
Response {
    Answer: "Go的特点包括...",
    Citations: [1, 2]
}
  ↓
保存到对话: Conversation.Messages
```

### 关键点

1. **上下文管理**: 智能截取最近N条消息
2. **历史集成**: 将对话历史加入提示词
3. **引用追踪**: 保持引用一致性
4. **状态持久化**: 保存对话状态（可选）

## 异步任务流程

### 流程图

```
提交任务 (JobQueue.Submit)
  ↓
持久化任务 (JobStore.Create)
  ├─ 状态: pending
  └─ 保存到数据库
  ↓
加入队列 (channel 或 Redis)
  ↓
Worker获取任务
  ↓
更新状态 (JobStore.Update)
  ├─ 状态: processing
  └─ 进度: 0%
  ↓
执行Handler
  ├─ 设置进度回调
  ├─ 处理业务逻辑
  │   ├─ 更新进度: 10%, 30%, 50%...
  │   └─ 更新阶段: "parsing", "chunking"...
  └─ 返回结果或错误
  ↓
更新最终状态 (JobStore.Update)
  ├─ 成功: status=completed, progress=100%
  └─ 失败: status=failed, error=...
  ↓
任务完成
```

### 数据转换

```
Job {
    ID: "job-123",
    Type: "document_ingest",
    Status: "pending",
    Progress: 0
}
  ↓
处理中更新:
Job {
    Status: "processing",
    Progress: 50,
    CurrentStage: "embedding",
    StageMessage: "Generating embeddings...",
    ProgressHistory: [
        {Progress: 10, Stage: "parsing", ...},
        {Progress: 30, Stage: "checking", ...},
        {Progress: 50, Stage: "embedding", ...}
    ]
}
  ↓
完成:
Job {
    Status: "completed",
    Progress: 100,
    CurrentStage: "complete",
    Result: "Document processed successfully"
}
```

### 关键点

1. **状态追踪**: 实时更新任务状态
2. **进度更新**: 阶段化进度追踪
3. **持久化**: 任务状态持久化到数据库
4. **错误处理**: 失败时记录详细错误信息

## 数据流总结

### 核心流程

1. **文档摄取**: 文件 → Document → Chunks → Vectors → 存储
2. **查询处理**: Query → Vector → Search → Rerank → Prompt → LLM → Answer
3. **对话管理**: Message → History → Retrieve → Prompt → LLM → Response
4. **异步任务**: Submit → Queue → Worker → Handler → Update → Complete

### 数据特点

1. **流式处理**: 大文档流式处理，避免内存溢出
2. **批量处理**: Embedding和存储批量处理，提高效率
3. **缓存机制**: Embedding和查询结果缓存，减少重复计算
4. **原子操作**: 文档存储使用事务，保证一致性

### 性能优化

1. **异步处理**: 耗时操作异步化，不阻塞API
2. **并行处理**: 向量检索和BM25检索并行执行
3. **批量操作**: 减少网络往返和数据库操作
4. **缓存命中**: 减少API调用和计算成本
